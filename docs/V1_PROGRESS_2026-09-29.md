# V1 diagnostics and feedback recovery

This slice adds an operator-visible local diagnostic path and fixes misleading feedback-save behavior. It does not deploy DeepSpec or establish public-launch readiness.

## Changes

- Default-off server identification diagnostics emit a small allowlisted event for each completed identification-service invocation. Provider fallback calls are not counted separately. Exceptions and log-sink failures preserve the original result/error behavior. No request image, prompt, prediction, account ID or raw exception message is included.
- The private log summarizer accepts a bounded export, validates exact fields, deduplicates repeated events, rejects conflicting IDs, and shows at most 20 recent failures. It creates no external telemetry endpoint or database.
- Saved-result feedback failures now show the device-storage warning and an explicit unsaved message. The correction remains in memory with a retry button. A later successful correction also persists a rating whose earlier write failed. Users are told to keep the page open or copy their text; unsaved edits are not promised to survive reload.
- Ordinary correction edits and correction-only retries preserve a newer rating from another tab. Saving an inspection on the same page preserves pending feedback until it is successfully retried.
- QA no longer discovers stale copies inside `.claude/worktrees/`; those files are preserved. Git and lint also exclude nested worktrees.
- The seller trial checklist now verifies the existing schema/migration history and includes optional private-log review. Timing, real functional checks and save/reopen evidence remain required.
