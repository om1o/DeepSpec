# Mechanic HTML handoff

`buildInspectionReportHtml(snapshot, options)` renders a frozen `InspectionReportSnapshot` into a static, downloadable HTML document. It does not fetch, save, call a model, or change source records. `getInspectionReportFilename(snapshot)` returns a date-only filename without vehicle or customer identifiers.

The snapshot collector supplies the root scan, its local component map, every directly linked scan, embedded images and an inventory of unavailable evidence. The renderer deduplicates scan sections and repeated image bytes while preserving every saved component/photo-group association, including distinct link IDs with identical photos. All saved components remain listed, including unboxed and not-visible components. Conflicting cloud map content is not merged into the selected local snapshot; the report identifies the conflict, revisions and unacknowledged saves.

Original photos retain their supplied bytes. Optional CSS-only outlines are a separate display layer, included when printed. Scan selection geometry applies only to the first original photo; map regions use their explicit source photo ID. Textual condition-region labels do not create geometry. Corrected crops link to the saved rectangular selection on the original and never reuse stale mask pixels. Actual saved mask cutouts are labeled separately. Identical embedded images can be referenced again by anchor instead of duplicating their bytes.

Condition observations retain links to declared photo IDs even when an image could not be embedded. Invalid condition references are omitted with an explicit inventory entry. Possible causes, unknowns, the next evidence request and purpose, specific safety actions, AI dimension methods and caveats, corrected labels, and self-reported human inspection records remain distinct. The report does not certify condition, fitment, function or safety. No repair timeline or structured human measurement log is inferred.

Stored capture mode, analysis source and saved/creation timestamps are qualified: cloud scan restoration can supply defaults for these fields, including in subsequently cached local records. They do not prove camera use or model execution. Separately recorded model-run details are preserved when available.

VIN and private scan/vehicle notes are excluded unless separately requested in options. Component notes and human inspection notes are included as inspection evidence. Customer, plate, job, technician and inspector identity fields, chat messages and cached customer reports are never serialized. Saved free text and photo pixels can still contain identifying information; images may retain metadata. Export UI should disclose these limits before download.

Every text value and attribute is escaped. Images must use PNG, JPEG or WebP base64 data URIs with matching raster signatures; SVG, remote URLs and malformed data are rejected independently of the collector. Reference URLs are rendered as text only. A restrictive content security policy blocks scripts, external assets, objects, forms and base URLs. The final UTF-8 HTML is limited to 64 MiB; overflow throws instead of silently dropping evidence.

Focused tests cover complete 12-component maps, repeated scan links, missing-photo observation anchors, source-specific outlines, mask versus corrected crop behavior, safety and uncertainty, per-scan vehicles, explicit privacy options, hostile content, rejected assets, cloud conflicts, legacy photo IDs, immutable inputs and the hard size limit. Browser acceptance should verify the real download and offline rendering, outline controls, readable narrow layout and print presentation. Unit tests alone do not establish those browser outcomes.
